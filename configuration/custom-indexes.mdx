---
title: 'Create a custom index'
description: 'Define a custom index with your own schema, tokenizers, and retention from the Create index form in Rootprint.'
---

The bundled `otel-logs-v0_9` index works for any application that emits OpenTelemetry logs. For everything else (audit trails, third-party log formats, application events with a specialized schema), create an index with the fields and types your data needs.

Open **Settings → Indexes → Create index**. When you save, Rootprint creates the index in Quickwit and opens its detail page, where you [map its fields](/configuration/manage-indexes#field-role-mappings) into the search UI. The same form is available over the API as `POST /api/indexes`; see the [Index management API](/api/overview).

## Index ID

<Frame>
	<img src="/images/indexes/create-index-top.png" alt="Create index form: Index ID, Mode, and Timestamp field" />
</Frame>

An index ID starts with a letter and runs 3–255 characters of letters, digits, `-`, or `_`. Ingest requests never name it. The ingest API key you scope to this index is what routes writes here.

## Mode

The schema mode decides what Quickwit does with fields you didn't declare in the field mappings.

| Mode      | Behavior                                                                                                                            |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `dynamic` | Default. Unknown fields are stored under a JSON catch-all and remain searchable. Most flexible — recommended unless you need strict validation. |
| `lenient` | Unknown fields are silently dropped at indexing. A stable schema without noisy errors from extra fields.                            |
| `strict`  | Unknown fields cause Quickwit to reject the document. The bundled `otel-logs-v0_9` index uses this mode.                            |

## Timestamp field

Pick the `datetime` field the index uses as its time axis. You must define at least one `datetime` field before you can pick one here. Time-range searches and retention both use this field. The timestamp field is always `fast`, so the field editor hides its `fast` toggle.

## Fields

<Frame>
	<img src="/images/indexes/create-index-fields.png" alt="Create index field editor: a field with its type, tokenizer, and per-type options" />
</Frame>

Add a row per field with **Add field**, then set its name, type, and options. At least one field is required. New fields start with `indexed`, `stored`, and `fast` on.

### Field types

`text` (searchable strings), `i64` and `u64` (signed and unsigned integers), `f64` (floating point), `datetime`, `bool`, `ip` (IPv4 or IPv6 addresses), and `json` (free-form key-value objects).

### Indexed, stored, and fast

Every field exposes three toggles:

- **Indexed**: the field is added to an inverted index and is searchable. When off, you cannot use the field in search predicates.
- **Stored**: the field's value is kept and returned in search results.
- **Fast**: the field is kept in column-oriented storage, enabling efficient range queries, aggregations, and sorting.

A field can be fast without being indexed, and the other way around.

### Per-type options

Depending on the field type, the editor exposes extra options:

| Type            | Options                                                                                                                              |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `text`          | **tokenizer**; **record**; **fieldnorms** (store field-length norms for scoring)                                                    |
| `json`          | **tokenizer**; **record**; **expand dots** (treat `a.b` keys as nested `a` → `b`)                                                    |
| `i64` / `u64` / `f64` | **coerce** (accept numbers sent as strings)                                                                                   |
| `datetime`      | **input formats**: how incoming values are parsed. Tick any of `rfc3339`, `iso8601`, `rfc2822`, `unix_timestamp`, and add custom [strptime](https://docs.rs/chrono/latest/chrono/format/strftime/index.html) patterns one per line. **output**: `rfc3339` or `unix_timestamp_secs`/`millis`/`micros`/`nanos`. **precision** of the fast column: `seconds`, `milliseconds`, `microseconds`, or `nanoseconds`. |

**Record** sets how much term data the inverted index keeps: `basic` (which documents contain the term), `freq` (also term frequency), or `position` (also token positions, required for phrase queries).

`text` and `json` fields also have a **default search** checkbox. Tick it to search the field when a query doesn't name one, so `timeout` matches `message:timeout` without the user typing the field.

### Tokenizers

`text` and `json` fields take a tokenizer, which decides how the value is split for search. Tokenization happens at index time and cannot be changed without recreating the index.

| Tokenizer                    | Behavior                                                          | Use for                                       |
| ---------------------------- | ----------------------------------------------------------------- | --------------------------------------------- |
| `raw`                        | Whole value as one token. Case-sensitive.                         | IDs, enums, hostnames, log level labels       |
| `raw_lowercase`, `lowercase` | Whole value as one token, lowercased. The two behave the same.    | Enum-like fields matched regardless of case   |
| `default`                    | Splits on whitespace and punctuation, lowercases.                 | Free-text search on message bodies            |
| `en_stem`                    | `default` plus English stemming (`running` → `run`).              | Free-text with morphological matching         |
| `whitespace`                 | Splits on whitespace only; keeps case and punctuation.            | Text where punctuation is significant         |
| `chinese_compatible`         | Per-character CJK splitting plus `default` behavior.              | Mixed CJK and Latin text                      |

For most application logs, follow the bundled index: `raw` for `severity_text` and `service_name`, and `default` for `body`.

## Retention

Enable retention to drop splits older than a fixed window. **Period** accepts durations like `48 hours`, `90 days`, `12 months`, or `2 years`. **Schedule** sets how often the cleanup runs (`hourly`, `daily`, `weekly`, `monthly`, `yearly`, or a cron expression) and defaults to daily when left blank.

Retention deletes whole splits, so a document can outlive the period by hours.

## Other settings

<Frame>
	<img src="/images/indexes/create-index-options.png" alt="Create index form: retention, index URI, tag fields, commit timeout, store source, and field presence" />
</Frame>

The rest of the form is optional, and most deployments leave it at the defaults:

| Setting                  | What it does                                                                                                                             |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Index URI**            | Where splits are stored. Defaults to the configured index root. Set it to put this index on a different bucket or path.                 |
| **Tag fields**           | Low-cardinality field names (one per line) indexed so the engine can skip data efficiently before scanning. |
| **Commit timeout (secs)** | How long indexing waits before forcing a commit. Defaults to `60`. Lower it to make new documents searchable sooner, at the cost of more, smaller splits. |
| **Store source**         | Keep the original document JSON in the index alongside the mapped fields.                                                                |
| **Index field presence** | Track which fields exist per document so presence queries (does this field exist?) work.                                                 |

## Use it from Rootprint

Saving the form lands you on the new index's detail page. To finish wiring it up:

1. On the **Configuration** tab, set the [field-role mappings](/configuration/manage-indexes#field-role-mappings) so the message, log level, and traceback render correctly.
2. Create an [ingest API key](/api/overview) scoped to the index and route writes through the [HTTP endpoint](/send-logs/http). Don't send OTLP to a custom-schema index: Quickwit answers `200` and discards the logs. See [Index target](/send-logs/otlp#index-target).
