The Rootprint search box accepts [Lucene query syntax](https://quickwit.io/docs/reference/query-language). Queries combine field-scoped clauses with boolean operators, and the same syntax works whether you type it in the UI or pass it to the search API.

## Quick reference

| Clause            | Example                                                            | Matches                                           |
| ----------------- | ------------------------------------------------------------------ | ------------------------------------------------- |
| Term              | `severity_text:ERROR`                                              | Exact token in the field                          |
| Term prefix       | `service_name:api*`                                                | Tokens starting with `api`                        |
| Phrase            | `body.message:"connection timeout"`                                | Exact word sequence (see [Limits](#limits))       |
| Phrase prefix     | `body.message:"connection tim"*`                                   | Phrase whose last token is a prefix (see [Limits](#limits)) |
| Term set          | `service_name:IN [api worker cron]`                                | Any of the listed tokens                          |
| Range (inclusive) | `severity_number:[13 TO *]`                                        | `>= 13`                                           |
| Range (exclusive) | `duration_ms:{100 TO 500}`                                         | `> 100` and `< 500`                               |
| Range (half-open) | `severity_number:>=17`                                             | `>= 17`                                           |
| Exists            | `attributes.user_id:*`                                             | Documents where the field is present              |
| Match all         | `*`                                                                | Every document                                    |
| Boolean           | `severity_text:ERROR AND service_name:api`                         | Both clauses match                                |
| Negation          | `NOT service_name:cron` or `-service_name:cron`                    | Documents that don't match                        |
| Grouping          | `(severity_text:ERROR OR severity_text:WARN) AND service_name:api` | Force precedence                                  |

Operator precedence: `NOT` / `-` > `AND` > `OR`. Use parentheses when you need a different order.

## Field paths

Use dot notation to reach nested JSON fields:

```text
attributes.http.method:POST
resource_attributes.k8s.namespace:production
body.error.stacktrace:"TypeError"
```

A key that itself contains a dot, such as `{"k8s.pod.name": "web-7f4"}`, needs no escaping when the field has `expand_dots: true`, as `attributes` and `resource_attributes` do in the bundled OTel index. If `expand_dots` is false, escape the literal dots with a backslash:

```text
# expand_dots: true
attributes.k8s.pod.name:web-7f4

# expand_dots: false
attributes.k8s\.pod\.name:web-7f4
```

## Default search fields

A query without a field name searches the index's `default_search_fields`. The bundled `otel-logs-v0_9` index searches `body.message`:

```text
timeout    → body.message:timeout
```

To search a different field, name it explicitly: `attributes.exception.type:ValueError`.

## Tokenizers and case sensitivity

A field's index-time tokenizer decides how queries against it match. The two tokenizers used in the bundled OTel index:

| Tokenizer | Used by                                         | Match behavior                                                      |
| --------- | ----------------------------------------------- | ------------------------------------------------------------------- |
| `raw`     | `severity_text`, `service_name`, `attributes.*` | The whole value is one token. Case-sensitive, exact match only.     |
| `default` | `body`                                          | Splits on whitespace and punctuation, lowercases. Free-text search. |

This means `severity_text:error` will **not** match a document with `"severity_text": "ERROR"`. Match the case your shipper sends, or filter via the UI quick-filters which know each field's casing.

If exact-match terms are missing on a custom index, check the field's tokenizer. See [Create a custom index](/configuration/custom-indexes#tokenizers).

## Time ranges

The UI's time picker bounds every query, so you don't write a timestamp clause. When you call the log endpoint directly, pass `startTs` and `endTs` in **seconds**, whatever the field's precision, and authenticate with a [query API key](/api/query-logs):

```http
GET /api/indexes/{indexId}/logs?q=severity_text:ERROR&startTs=1776340000&endTs=1776343600
```

## Common log search recipes

```text
# Errors and worse from a specific service
severity_number:[17 TO *] AND service_name:api-gateway

# A request ID in log or resource attributes
attributes.request_id:abc-123 OR resource_attributes.request_id:abc-123

# 5xx responses with slow latency
attributes.http.status:[500 TO 599] AND attributes.duration_ms:>1000

# All logs that carry a stacktrace
attributes.exception.stacktrace:*

# Exclude noise from cron and health checks
NOT service_name:IN [cron healthcheck] AND severity_text:ERROR

# Correlate with a distributed trace
trace_id:4bf92f3577b34da6a3ce929d0e0e4736
```

<Tip>
	Pasting a bare trace ID into the search box opens the trace. Wrap it in quotes to search it as text. See [Read a trace](/traces/explore#open-a-trace).
</Tip>

## Escaping special characters

These characters are reserved by the query parser and must be backslash-escaped to appear in a value:

```
+ ^ ` { } " [ ] ( ) ~ ! \ * <space>
```

Inside quotes, reserved characters need no escaping. Outside quotes, escape them: `body.message:\(test\)`.

## Limits

- Phrase and phrase-prefix queries need a field indexed with `record: position`. No field in the bundled `otel-logs-v0_9` index sets it, so combine terms instead: `body.message:connection AND body.message:timeout`.
- IP fields don't accept CIDR notation. Use a range instead: `client_ip:[10.0.0.0 TO 10.0.0.255]`.
