---
title: 'Send logs with the OpenTelemetry Collector'
description: 'Tail log files with the OpenTelemetry Collector — on bare metal or in Docker — and ship them to Rootprint over OTLP.'
---

The [OpenTelemetry Collector](https://opentelemetry.io/docs/collector/) tails log files and ships each line to Rootprint over OTLP. Records land in the index your ingest API key is scoped to: `otel-logs-v0_9` in this guide.

## Prerequisites

- A running Rootprint instance. Substitute its host for `<your-rootprint>`.
- An **ingest API key** scoped to `otel-logs-v0_9`. Create one in **Settings → API keys** with **Create ingest key**, then substitute it for `<your-ingest-api-key>`. See [API keys](/api/overview).
- A Linux host, with Docker Compose if you run the Collector in a container.
- The Collector **Contrib** distribution (`otelcol-contrib`), v0.149 or newer. The core distribution has no `file_log` receiver.

<Steps>
  <Step title="Write the config">
    Replace `<your-rootprint>`, `<your-ingest-api-key>`, the `include` glob, and `myapp` with your
    service name.

    ```yaml
    receivers:
      file_log:
        include:
          - /var/log/myapp/*.log
        start_at: end
        resource:
          service.name: myapp

    processors:
      batch: {}

    exporters:
      otlp_http:
        logs_endpoint: https://<your-rootprint>/v1/logs
        compression: gzip
        headers:
          Authorization: "Bearer <your-ingest-api-key>"

    service:
      pipelines:
        logs:
          receivers: [file_log]
          processors: [batch]
          exporters: [otlp_http]
    ```

    `start_at: end` reads only lines written after the Collector starts. Set it to `beginning` for a
    one-time backfill.
  </Step>

  <Step title="Run the Collector">
    <Tabs>
      <Tab title="Bare Metal">
        Install `otelcol-contrib` from the
        [Collector installation page](https://opentelemetry.io/docs/collector/installation/). The
        Debian and RPM packages run the `otelcol-contrib` service as the `otelcol-contrib` user and
        read `/etc/otelcol-contrib/config.yaml`.

        1. Save the config as `/etc/otelcol-contrib/config.yaml`.
        2. Let the service user read the log files. On Debian/Ubuntu, `/var/log` files usually
           belong to the `adm` group:

           ```bash
           sudo usermod -aG adm otelcol-contrib
           ```

           Alternatively, `sudo chmod a+r` the log files. That opens them to every user on the host.
        3. Restart the service and check its log for config or exporter errors:

           ```bash
           sudo systemctl restart otelcol-contrib
           sudo journalctl -u otelcol-contrib -n 20
           ```
      </Tab>

      <Tab title="Docker">
        Save the config as `otel-config.yaml` next to your `docker-compose.yml`, and add this
        service. The bind mount keeps the `/var/log/myapp` path the same inside the container.

        ```yaml
        services:
          rootprint-otelcol:
            image: otel/opentelemetry-collector-contrib:latest
            container_name: rootprint-otelcol
            restart: unless-stopped
            command: ["--config=/etc/otelcol/config.yaml"]
            volumes:
              - ./otel-config.yaml:/etc/otelcol/config.yaml:ro
              - /var/log/myapp:/var/log/myapp:ro
        ```

        ```bash
        docker compose up -d rootprint-otelcol
        ```

        The container runs as a non-root user. If it logs `permission denied`, add `user: root` to
        the service or run `sudo chmod a+r /var/log/myapp/*.log`.
      </Tab>
    </Tabs>
  </Step>

  <Step title="Send a test log line">
    ```bash
    sudo mkdir -p /var/log/myapp
    echo "$(date -Iseconds) hello from the otel collector" | sudo tee -a /var/log/myapp/test.log
    ```
  </Step>

  <Step title="Verify in Rootprint">
    Open **Logs**, pick `otel-logs-v0_9` from the index selector, and search for
    `hello from the otel collector`. Records typically appear within 5–10 seconds.
  </Step>
</Steps>

## What the config does

- **`file_log`**: emits one record per line, with the raw line in `body`. To parse fields out of the line, add a `json_parser` or `regex_parser` under the receiver's `operators`.
- **`resource`**: sets the `service.name` resource attribute, which fills Rootprint's `service_name` column.
- **`logs_endpoint`**: the full URL, including `/v1/logs`. Don't use `endpoint`, which appends the path itself.
- **`batch`**: groups records before export. Tune `send_batch_size` and `timeout` for latency or batch size.

## Troubleshooting

- **`unknown type: "file_log"`** or **`unknown type: "otlp_http"`** on startup: you are running the core Collector or a Contrib release older than v0.149. Install or upgrade `otelcol-contrib`.
- **401/403/413/415**: see [Response codes](/send-logs/otlp#response-codes).
