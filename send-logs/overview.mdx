Rootprint accepts logs two ways:

- **OTLP HTTP**: OpenTelemetry logs over HTTP (protobuf). Use this with any OTEL SDK, the OTEL Collector, or a sidecar that speaks OTLP. Records land in the index your ingest token is scoped to.
- **Rootprint HTTP endpoint**: an authenticated endpoint that forwards NDJSON straight to a Quickwit index. Use this when you control the wire format and want to write to a custom-schema index.

## Pick a path

| If you have…                                 | Use                                                                                      |
| -------------------------------------------- | ---------------------------------------------------------------------------------------- |
| An app in Python, Node.js, Go, or Zig        | The matching [language page](#languages) (OTLP SDK)                                      |
| Access logs from Caddy or Nginx              | The matching [web server page](#web-servers)                                            |
| Container logs on a Linux host               | [Docker](/send-logs/platforms/docker) (OTEL Collector)                                   |
| Logs already on disk on a Linux host         | [OpenTelemetry Collector](/send-logs/log-agents/otel-collector), [Fluent Bit](/send-logs/log-agents/fluent-bit), or [Vector](/send-logs/log-agents/vector) |
| Existing pipeline that emits your own schema | [HTTP endpoint](/send-logs/http)                                                        |
| An app in another language, or anything else that speaks OTLP | [OTLP reference](/send-logs/otlp)                                       |

## Before you start

Every path requires an **ingest API key**. API keys are created in **Settings → API keys** and are scoped to a single index: one key, one index. Pick the index you want to write to, create an ingest API key for it, and keep the value ready for the integration page you follow.

<Note>
	The built-in `otel-logs-v0_9` index is created on first boot, so there's an OpenTelemetry-ready
	index to scope a token to without any extra configuration. See [Indexes](/indexes) for its schema.
</Note>
